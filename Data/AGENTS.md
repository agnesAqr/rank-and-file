# Data/ 작업 규칙

콘텐츠는 데이터다. AI는 후보를 많이 만들고, 거르는 일은 검사기와 사람이 한다. 루트 `AGENTS.md`를 먼저 읽는다.

| 폴더 | 내용 | AI가 써도 되는가 |
|---|---|---|
| `defs/units.json`, `defs/rules.json` | 병과 수치, 규칙 매개변수 | 사람이 정한 값을 옮겨 적을 때만 |
| `candidates/roundN/` | AI가 낸 후보 | 된다. 후보는 여기에만 쓴다 |
| `accepted/squads.json`, `relics.json`, `formations.json` | 채택본 | 사람이 후보 id를 짚어 채택을 지시했을 때만 |
| `reports/` | 관문 기록, BalanceSim CSV | 도구가 쓴다. 손으로 고치지 않는다 |

## 세 관문

| 관문 | 검사하는 쪽 | 검사 | 통과 기준 [초기값] |
|---|---|---|---|
| 1 스키마 | `node tools/validate_content.js` | 필수 필드, 어휘 밖의 값, 값 범위, 칸 연결성, 회전 중복, 이름 8자 | 하나라도 어기면 탈락 |
| 2 기여도 | BalanceSim, 후보당 1만 판 | 후보를 넣은 덱과 뺀 덱의 승률 차이 | +2~+8%p |
| 2 독주 | 같음 | 후보가 들어간 두 장 조합의 승률 | 어떤 조합도 70% 이하 |
| 2 중복 | 같음 | 기존 카드와 효과 벡터의 코사인 유사도 | 0.9 미만 |
| 2 해골 진형 | 같음 | 배정된 밤에서 탐색 봇의 승률 | 목표 곡선 ±5%p |
| 3 사람 | 직접 플레이 | 설명만 읽고 효과를 예측해 실제와 비교, 고를 이유가 있는지 | 예측이 틀리면 설명이 아니라 효과를 고친다 |

목표 곡선(밤 1~12의 탐색 봇 승률): 90, 86, 82, 70, 78, 74, 70, 58, 66, 60, 54, 45%.

- 관문 1·2를 통과해도 채택이 아니다. 무엇을 넣을지는 사람이 플레이해 보고 정한다.
- 통과 기준은 사람이 정한다. 통과율이 낮다고 기준을 넓히거나 검사를 빼지 않는다.
- 탈락한 후보를 지우지 않는다. 회차 폴더에 그대로 두어야 통과율의 근거가 남는다.
- 탈락 사유는 JSON으로 모아 다음 회차의 생성 요청에 붙인다.
- 회차마다 `reports/gates.csv`에 한 줄을 더한다: 회차, 종류, 후보 수, 관문 1 통과, 관문 2 통과, 채택, 가장 많은 탈락 사유.

## 후보를 만들 때

- 정해진 어휘만 조합한다. 새 효과가 필요해 보이면 만들지 않고 제안으로 남긴다. 어휘 추가는 사람이 하고 테스트를 붙인다.
- 카드 설명문을 쓰지 않는다. 설명은 조각에서 템플릿으로 만든다. `desc` 같은 필드를 더하지 않는다.
- 이름은 8자 이하다. 기존 게임, 작품, 인물의 이름을 쓰지 않는다.
- 한 회차의 분량은 분대 60, 유물 30, 해골 진형 90이다. 출시 목표는 24, 12, 36이다.
- 생성 요청에는 스키마, 설계 기둥, 기존 카드 요약, 지난 회차의 탈락 사유를 함께 넣는다.

## 형식

식별자 문자열의 기준은 `tools/validate_content.js`의 목록이다. 아래 예시에 없는 문자열을 지어내지 않는다.

분대

```json
{ "id": "sq_K_L3_02", "name": "성벽 방패대", "class": "K", "shape": [[0,0],[1,0],[1,1]], "tier": 2,
  "trait": { "when": "OnHit", "do": "Shield", "who": "Linked", "n": 2, "limit": 3 } }
```

- `class`: `K` 방패병, `B` 광전사, `R` 석궁수, `M` 마법사, `H` 척후.
- `shape`: [행, 열] 1~4칸. 칸은 상하좌우로 이어져야 한다. 같은 모양을 돌린 것은 중복이다. [미정] 거울상(예: L과 J)을 같은 모양으로 볼지는 정해지지 않았다.
- `trait`: 0~1개. 언제 5종(전투 시작, 공격할 때, 맞을 때, 처치할 때, 아군이 쓰러질 때) × 무엇 6종(공격+, 방어+, 회복, 보호막, 간격−, 성문 수리) × 누구 5종(자신, 링크된 이웃, 같은 열, 같은 분대, 아군 전체). `n`은 수치, `limit`은 전투당 발동 횟수다.

해골 진형

```json
{ "id": "fm_n07_a", "night": 7, "kind": "normal", "rows": ["wwmmww", "mrmmrm", ".g..g.", "..rr.."] }
```

- `rows`: 4행 × 6자. 첫 줄이 행 0(최전열)이다. `m` 졸개, `w` 전사, `r` 궁수, `g` 술사, `.` 빈칸.
- `night`: 1~12. 밤마다 3개를 둔다. 4·8번째 밤은 정예, 12번째 밤은 우두머리다.

유물

```json
{ "id": "rl_dawn_bell", "name": "새벽의 종", "effect": { "kind": "Rule", "param": "MaxTicks", "delta": -50 } }
```

- [미정] 유물과 특성의 처리 시점이 정해지지 않았다(`docs/design.md` 6.8절). 정해지기 전에는 이 형식을 늘리지 않는다.

id는 분대 `sq_{병과}_{모양}_{번호}`, 진형 `fm_n{밤 두 자리}_{a~c}`, 유물 `rl_{영문 소문자와 밑줄}`이다. 채택된 id는 바꾸지 않는다. 리포트와 결정 기록이 id로 가리킨다.

## defs

- `units.json`: 병과 9종(`K`, `B`, `R`, `M`, `H`, `m`, `w`, `r`, `g`)의 체력, 공격, 방어, 간격, 사거리, 표적, 마법 여부, 부활 값, 링크 효과.
- `rules.json`: 열 6, 행 4, 최대 600틱, 성문과 결계 60, 성문 피해 1.
- 지금 값은 [초기값]이다. 조정안은 낼 수 있지만 값은 사람이 정한다.
- 값을 바꾸면 순서대로 한다: 참조 구현의 상수를 맞춘다 → `node tools/export_golden.js` → `tools\run_tests.bat` → 문서의 [산정] 수치를 다시 계산한다 → `docs/decisions.md`에 전후 값과 근거를 적는다.

## reports

- CSV는 도구가 낸 그대로 둔다. 숫자를 손으로 고치지 않는다. 요약과 해석은 따로 적는다.
- 리포트마다 조건을 남긴다: 명령, 시드, 판 수, 콘텐츠 버전 해시, 커밋.
- 같은 명령과 같은 시드는 같은 CSV를 내야 한다. 다르면 버그로 알린다.
- 콘텐츠 버전 해시는 채택본 JSON 3개와 `defs` 2개의 내용을 FNV-1a로 묶은 값이다. `accepted/`나 `defs/`가 바뀌면 해시가 바뀐다. 예전 해시로 잰 수치를 지금 콘텐츠의 수치처럼 쓰지 않는다.
