# RankGame 작업 규칙

화면, 입력, 런 진행을 맡는다. 전투 결과는 계산하지 않는다. 루트와 `Source/AGENTS.md`를 먼저 읽는다.

## 코어와의 경계

| 필요한 것 | 얻는 방법 |
|---|---|
| 전투 결과 | `Rank::Simulate`를 한 번 부르고 `FBattleResult`를 보관한다. 승패는 여기서 정해진다 |
| 전투 화면 | 이벤트 로그를 시간 순서로 재생한다. 체력은 이벤트의 값을 빼서 표시한다 |
| 링크와 최종 능력치 미리보기 | `Rank::ComputeLinks` |
| 분대를 놓을 수 있는지 | `FFormationMask::CanPlace` |
| 승패 문구와 종류 | `Rank::Judge` |

- 피해, 표적, 사거리, 링크 식을 이 모듈에 다시 쓰지 않는다. 화면에 필요한 값이 코어에 없으면 코어에 함수를 더하자고 제안한다.
- 재생 속도(1배속, 2배속, 건너뛰기), 일시정지, 프레임 시간은 결과를 바꾸지 않는다. 결과는 재생을 시작하기 전에 정해져 있다.
- `float`은 연출(위치 보간, 카메라)에만 쓴다.
- 콘텐츠를 읽는 경로는 하나다: JSON → 행 구조체 → 코어 구조체. 행 구조체(`USTRUCT`)와 변환 함수는 이 모듈에 하나만 둔다. 임포터와 시뮬레이터도 같은 함수를 쓴다.

## 런 진행

- `URunSubsystem`(`UGameInstanceSubsystem`)이 덱, 배치, 그 밤의 해골 진형을 `FBattleInput`으로 묶는다. 전투 계산은 하지 않는다.
- 흐름: 메인 메뉴 → 보상 → 배치 → 전투 → 결과 → 다음 밤의 보상 또는 런 종료.
- 배치 단계에서는 모든 분대를 다시 놓을 수 있고, 놓지 않은 분대는 예비 2칸에 둔다(기획서2 §3).
- 12밤이다. 4·8번째 밤은 정예, 12번째 밤은 우두머리다. 패배가 3번 쌓이면 런이 끝난다. 보상은 3장 가운데 1장이고, 섬멸로 이긴 다음 밤에는 다시 뽑기를 1번 준다.
- `FRunState`에 시드, 난수 상태, 밤, 패배 수, 덱, 유물, 직전 배치, 선택 이력, 콘텐츠 버전 해시를 둔다.
- 난수는 런 전용 정수 난수기 하나만 쓴다. 보상 카드와 해골 진형을 고를 때만 부르고, 상태를 `FRunState`에 둔다. 엔진 난수 함수를 부르지 않는다.
- 시드와 선택 이력만으로 런 전체를 다시 만들 수 있어야 한다. 같은 시드로 두 번 돌린 런은 결과가 같다(T9).

## 전투 재생

- 1틱은 0.1초다. 유닛마다 액터 하나를 두고, 위치는 열과 대열 순번에서 정한다. 대열 전진만 보간한다.
- 개발 빌드에서는 재생이 끝난 화면의 생존 수와 성문 값이 `FBattleResult`와 같은지 검사한다(T10). 이 검사가 Shipping의 동작을 바꾸면 안 된다.
- 애니메이션은 먼저 `USkeletalMeshComponent::PlayAnimation`으로 이벤트마다 시퀀스를 직접 재생한다. 이 방식에는 동작 사이 블렌딩이 없다. 끊겨 보이면 사람에게 알린다. 사람이 에디터 조정으로 넘어가기로 하면, C++ `UAnimInstance` 하위 클래스에 상태 값을 두고 애니메이션 블루프린트는 애니메이션 그래프만 갖게 한다(`Source/AGENTS.md`).
- 이벤트별 애니메이션 이름은 `docs/design.md` 8.2절의 표를 따른다. 표에 없는 이름을 짐작으로 쓰지 않는다.
- 병과별 메시와 애니메이션은 데이터 에셋(`DA_`)에서 읽는다. 경로 문자열을 코드에 쓰지 않는다.

## UI

- UI의 동작은 전부 C++이다. 위젯 블루프린트는 C++ 위젯 클래스를 부모로 하고 배치와 모양만 담는다. 이벤트 그래프에 노드를 두지 않는다.
- MVVM으로 나눈다. 뷰모델은 `RunVM`, `RewardVM`, `DeployVM`, `BattleVM`, `ResultVM`이고 C++ 클래스다. 값이 바뀌면 델리게이트로 알린다. UMG Viewmodel 플러그인은 쓰지 않는다(플러그인 최소화). 위젯은 뷰모델만 보고, 뷰모델은 런 상태와 코어 함수의 결과를 옮길 뿐 규칙을 계산하지 않는다.
- 카드 설명문은 특성 조각에서 템플릿으로 만든다. 설명 문자열을 데이터나 코드에 따로 적지 않는다.
- 레벨은 `L_Field` 하나다. 메뉴와 각 화면은 같은 전장 위에 UI로 띄운다.
- 해상도와 창 모드는 `UGameUserSettings`로 정하고 적용한다. 음량은 마스터 하나만 둔다.
- [미정] 위젯 배치를 처음부터 위젯 블루프린트 디자이너로 할지, 코드로 배치하고 조정값만 에디터에 열어 둘지, 그리고 배치 입력 방식(격자 위젯, 3D 판 위 조작)은 정해지지 않았다. 사람이 정하기 전에 한쪽으로 구현하지 않는다.
- [미정] 시작 덱, 밤별 기대 덱 크기, 저장과 이어하기도 정해지지 않았다. 임시 값을 쓸 때는 임시라고 표시하고 데이터에 둔다.

## Shipping에서 깨지기 쉬운 곳

- 코드가 경로 문자열로만 가리키는 에셋(DataTable 등)은 쿠킹에서 빠질 수 있다.
- Editor 모듈은 런타임 빌드에 없다. 이 모듈이 그 코드를 부르면 Shipping 빌드가 깨진다.
- 개발 빌드에서만 도는 검사가 Shipping에서 동작을 바꾸면 안 된다.

이 세 곳을 건드렸으면 `tools\package.bat`으로 Shipping 패키지를 만들어 확인한다.

## 검증

- `tools\run_tests.bat`: 콘텐츠 행 수(T8), 런 스모크(T9), 재생 일치(T10)가 통과해야 한다.
- 화면과 조작은 사람이 직접 한 판을 돌려 확인한다. AI는 화면을 보지 못했으면 "화면에서 확인하지 못함"이라고 적는다.
