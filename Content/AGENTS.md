# Content/ 작업 규칙

`.uasset`과 `.umap`은 바이너리다. 에디터 안에서만 만들고 고친다. AI는 Unreal MCP를 통해서만 에셋을 다룬다. 루트 `AGENTS.md`를 먼저 읽는다.

## AI가 하는 일과 하지 않는 일

- 에셋 파일을 텍스트나 스크립트로 직접 만들거나 고치지 않는다. 에셋 작업은 Unreal MCP(에디터 안에서 도는 MCP 서버)의 도구로만 한다.
- MCP로 하는 일: 위젯 블루프린트 생성·설정(UMG ToolSet, 부모는 C++ 클래스, 이벤트 그래프는 비움), 데이터 에셋 연결과 속성 설정(Editor 도구 묶음), 전장 액터·머티리얼 배치.
- AI가 하지 않고 사람이 에디터에서 하는 일: 캐릭터 임포트(임포트 창에서 Skeleton을 지정한다. MCP 임포트로는 Skeleton을 지정할 수 없다), 애니메이션 블루프린트(MCP로 만들 수 없다. 블렌딩은 시간이 남으면 하는 항목)(2026-11-21 AI 기능 결정 ④⑤).
- MCP 서버는 자동으로 뜨지 않는다. 쓸 때 에디터를 실행 인자 `-ModelContextProtocolStartServer`로 띄운다(127.0.0.1:8000, 2026-11-21 측정). MCP 클라이언트 설정 파일 `.mcp.json`은 커밋하지 않는다(11/21 결정 4 ③).
- MCP로 하지 않는 일: 게임 로직용 블루프린트 클래스, 레벨 블루프린트, 블루프린트 이벤트 그래프에 노드 추가.
- 결과는 숫자나 캡처로 확인하고 보고한다. 예: Skeleton 에셋 1개, `BindWidget` 대상 위젯 N개가 모두 있음, 이벤트 그래프 노드 0개, 화면 캡처. 확인하지 못한 것은 확인하지 못했다고 쓴다.
- MCP로 만들 수 없거나 실패하면 순서와 설정값을 적은 절차로 사람에게 넘긴다.
- 에셋 파일을 셸이나 탐색기로 옮기거나, 이름을 바꾸거나, 지우지 않는다. 옮기기와 이름 바꾸기는 에디터에서 한다. 에디터는 옛 위치에 리디렉터(redirector)를 남겨 참조를 잇는다([Epic: Asset Redirectors](https://dev.epicgames.com/documentation/en-us/unreal-engine/asset-redirectors-in-unreal-engine)).
- 캡처나 MCP 조회 결과 없이 "임포트됐다", "재생된다"라고 쓰지 않는다.

## 폴더

| 폴더 | 내용 | 규칙 |
|---|---|---|
| `Data/` | DataTable 에셋 | `RankEditor` 임포터가 `Data/accepted/*.csv`에서 만든다. 에디터에서 행을 손으로 고치지 않는다. 고칠 것은 CSV에서 고치고 다시 임포트한다 |
| `Characters/` | KayKit 캐릭터 9종 | Skeleton 에셋 하나를 9종이 함께 쓴다. 재생은 C++이 먼저 한다. 블렌딩 조정은 시간이 남으면 사람이 C++ 부모를 둔 애니메이션 블루프린트(`ABP_`) 하나를 만들어 9종이 함께 쓴다 |
| `Environment/` | 전장: 바닥, 원경, 소품 | 배경 이미지 3장은 AI로 만든다(아래) |
| `UI/`, `Audio/` | 위젯 블루프린트(`WBP_`), 글꼴, 아이콘 텍스처, 효과음 | 위젯 블루프린트는 C++ 위젯 클래스를 부모로 하고 배치와 모양만 담는다. 라이선스를 확인한 것만 넣는다 |
| `Data/Assets/` | 에셋 연결용 데이터 에셋(`DA_`) | C++ 데이터 에셋 클래스의 인스턴스. 병과별 메시와 애니메이션, 배경 텍스처를 담는다 |
| `Maps/L_Field.umap` | 전장 레벨 | 레벨은 이것 하나다. 메뉴와 각 화면은 이 전장 위에 UI로 띄운다 |

## 캐릭터 임포트

- 쓰는 모델은 9종이다: `Knight`, `Barbarian`, `Rogue`, `Mage`, `Rogue_Hooded`, `Skeleton_Minion`, `Skeleton_Warrior`, `Skeleton_Rogue`, `Skeleton_Mage`. 팩 미리보기에 있는 `Druid`와 `Engineer`는 유료 버전이라 쓰지 않는다.
- GLB(glTF 2.0) 파일을 쓴다. 9종은 관절이 41개이고 이름과 계층 순서가 같다.
- 첫 캐릭터를 임포트할 때 생긴 Skeleton을 나머지 8종의 임포트에서 지정한다. Skeleton 에셋이 둘 이상 생기면 공유에 실패한 것이다. 그대로 진행하지 않고 알린다. 임포트는 사람이 에디터 임포트 창에서 한다(2026-11-21).
- 애니메이션은 해골 파일 하나에서 한 번만 가져온다. 해골 쪽 95개가 모험가 쪽 76개의 이름을 모두 포함한다.
- 모험가 5종은 GLB에 붙은 투구·망토·무기·방패 메시를 그대로 쓰고, 여러 개인 방패·검은 하나만 남기고 숨긴다(2026-11-21 결정 4 ①). [미확인] 숨기는 방법(메시 구역 숨기기 등)은 임포트 결과를 보고 정한다.
- 해골 4종의 GLB에는 무기 메시가 없다(2026-11-21 측정). [미정] 해골 무기를 같은 팩의 별도 파일(`Assets/gltf/`)로 `handslot` 본에 붙일지, 무기 없이 둘지(결정 6 묶음 4에서 정한다).
- 이벤트별 애니메이션 이름은 `docs/design.md` 8.2절의 표를 따른다. 표에 없는 이름을 짐작으로 쓰지 않는다.
- Skeleton 공유가 안 될 때의 대응(IK Retargeter 등)은 사람이 정한다.
- 블루프린트는 에디터 조정용으로만 쓴다: C++ 부모를 둔 위젯 블루프린트와 애니메이션 블루프린트. 이벤트 그래프는 비워 둔다. 게임 로직용 블루프린트 클래스와 레벨 블루프린트는 만들지 않는다. 임포트할 때 애니메이션 블루프린트를 자동으로 만드는 옵션이 있으면 끈다. 필요해지면 C++ 부모를 지정해 사람이 만든다.

## 배경 이미지 (AI 생성)

[보류] 2026-11-21부터 배경 작업은 보류다(본인이 3D 생성 AI로 바꾸는 중). 아래 2D 사양과 기준은 방법이 정해질 때까지 그대로 둔다.

| ID | 텍스처 (`Environment/BG/`) | 크기 | 쓰는 곳 |
|---|---|---|---|
| BG-01 | `T_BG_GroundAlly` | 2048×2048, 이음새 없는 타일 | 아군 진형 바닥 |
| BG-02 | `T_BG_GroundEnemy` | 2048×2048, 이음새 없는 타일 | 해골 진형 바닥 |
| BG-03 | `T_BG_Backdrop` | 4096×1024 | 결계 뒤에 세우는 원경 |

고르는 기준이다. 하나라도 어기면 다시 만든다.

1. 바닥의 평균 명도가 0.28~0.38, 평균 채도가 0.25 이하다(코드로 잰다).
2. BG-02가 BG-01보다 조금 어둡다(명도 차 0.03~0.08, 코드로 잰다).
3. 바닥에 원근, 높이 있는 물체, 그림자, 칸 선이 없다.
4. 타일을 2×2로 이어 붙였을 때 경계가 보이지 않는다.
5. 강한 대각선이나 큰 무늬가 없다. 전투가 열 단위로 진행되는데 열이 흐려진다.
6. 캐릭터 9종을 진형판 크기로 올렸을 때 바닥에 묻히는 유닛이 없다. 팀 고리 없이 볼 때 마법사, 해골 궁수, 해골 술사는 예외로 둔다.
7. 원경의 아래쪽 색이 BG-02와 이어지고, 노랑·주황·보라 강조가 없다. 해골 눈, 등불, 결계의 색과 겹친다.
8. 글자, 워터마크, 기존 게임을 닮은 요소가 없다.

- 이미지에 그리지 않는 것: 성문, 결계, 칸 선, 전선, 팀 고리, 링크. 맞거나 바뀌어야 하는 요소라서 엔진에서 만든다.
- 프롬프트에 기존 게임, 회사, 작가의 이름을 넣지 않는다.
- 만든 날의 개발 일지에 도구, 프롬프트, 후보 수, 고른 것과 버린 것의 이유를 적는다.
- [미확인] 생성 도구의 이용 약관이 결과물을 공개 저장소와 포트폴리오에 쓰는 것을 허용하는지 확인하고, 확인 결과를 크레딧과 함께 적는다.

## 렌더링과 색

- Lumen, Nanite, 가상 그림자 맵(Virtual Shadow Maps)은 끈다. 노출은 수동(Manual)으로 고정한다.
- 색마다 뜻이 하나다: 청록은 아군, 붉은색은 적, 금색은 링크, 보라는 결계, 주황은 성문 등불, 노랑은 해골 눈. 배경과 UI에서 이 색을 다른 뜻으로 쓰지 않는다.
- 바닥은 유닛보다 어둡고 채도가 낮아야 한다. 유닛, 링크 표시, 체력 막대가 먼저 읽혀야 한다.

## 이름

접두사는 Epic 권장 규칙을 따른다([Epic: Recommended Asset Naming Conventions](https://dev.epicgames.com/documentation/en-us/unreal-engine/recommended-asset-naming-conventions-in-unreal-engine-projects)).

| 종류 | 접두사 | 종류 | 접두사 |
|---|---|---|---|
| 텍스처 | `T_` | 스켈레탈 메시 | `SK_` |
| 머티리얼 | `M_` | 스켈레톤 | `SKEL_` |
| 머티리얼 인스턴스 | `MI_` | 애니메이션 블루프린트 | `ABP_` |
| 스태틱 메시 | `SM_` | 애니메이션 시퀀스 | `AS_` |
| 데이터 테이블 | `DT_` | 위젯 블루프린트 | `WBP_` |
| 피직스 에셋 | `PHYS_` | | |

그 표에 없는 종류는 이 저장소에서 정한다: 레벨 `L_`, 머티리얼 파라미터 컬렉션 `MPC_`, 데이터 에셋 `DA_`. 게임 로직용 블루프린트 클래스(`BP_`)는 만들지 않는다.

## 라이선스와 크레딧

- 넣을 수 있는 것: KayKit 4팩(Adventurers, Skeletons, Halloween Bits, Dungeon Remastered, 모두 CC0), 이 프로젝트에서 직접 만든 것, 라이선스를 확인한 것.
- 에셋을 더하면 같은 변경 안에서 `README.md`의 크레딧에 출처, 저작자, 라이선스를 적는다. AI로 만든 이미지는 AI로 만들었다고 적는다.
- 사운드 팩은 내용과 라이선스를 아직 확인하지 않았다. 사람이 확인하기 전에는 넣지 않는다.
- 호박처럼 계절감이 강한 소품은 쓰지 않는다.
- 코드가 경로 문자열로만 가리키는 에셋은 쿠킹에서 빠질 수 있다. 코드에서 새 에셋을 가리키게 했으면 `tools\package.bat`으로 Shipping 패키지에서 확인한다.
