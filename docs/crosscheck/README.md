# 교차 검증 절차

AI가 계산한 기대값을 다른 회사 모델이 따로 계산한 값과 맞대어 확인하는 절차다(2026-11-20 결정, `docs/decisions.md`). 사람은 두 계산이 다른 시나리오만 본다. 지금 대상은 손계산 시나리오(T5, `Source/RankTests/Fixtures/hand_v1.json`)다.

상태: 2026-11-20 승인(확정 · 본인, `docs/decisions.md`). AI가 초안을 썼다.

## 무엇을 잡고 무엇을 못 잡는가

| | 내용 |
|---|---|
| 잡는다 | 계산 실수, 처리 순서 실수, 한쪽만 조항을 잘못 읽은 경우, 계산 과정과 다르게 옮겨 적은 기대값, 규칙 문서의 문장이 모호해서 두 모델이 다르게 읽은 곳 |
| 못 잡는다 | 두 모델이 같은 문장을 같은 식으로 잘못 읽은 경우 [판단]. 시나리오가 목적으로 적은 상황을 실제로 지나는지(값만 비교한다). 규칙 문서 자체가 의도와 다르게 적힌 경우 |

못 잡는 쪽은 변이 검사(`docs/design.md` 9.5)와 조항 대조표 리뷰(`docs/review/`)가 맡는다. 교차 검증이 통과했다고 그 둘을 줄이지 않는다.

## 역할

| 역할 | 누가 | 하는 일 | 보지 않는 것 |
|---|---|---|---|
| 계산 세션 | 기대값을 계산한 AI. 구현을 맡은 세션과 다른 세션이다 | `hand_v1.json`의 기대값과 계산 과정을 쓰고 고친다 | `Source/RankCore`, 테스트 실행 결과, 검증자의 결과 |
| 검증자 | 다른 회사 모델(Google Antigravity에서 실행). Claude 계열 모델은 고르지 않는다. 기대값을 계산하고 코어를 구현한 쪽이 Claude 계열이기 때문이다 | `hand_v1/INSTRUCTIONS.md`대로 처음부터 계산한다 | 기존 기대값, 계산 과정, 시나리오의 목적, 구현 코드, 테스트 결과, 비교 결과 |
| 작업 세션 | 구현을 맡은 AI 세션 | 눈가림 입력 만들기, 비교, 보고 | 기대값과 보고서의 값. 개수, 시나리오 id, 어긋난 항목 이름만 다룬다 |
| 본인 | 사람 | 검증자 실행, 다른 곳의 판정 | |

## 순서

1. **입력 만들기(작업 세션).** `node tools/hand_crosscheck.js export`. `hand_v1.json`에서 병과 수치, 규칙 매개변수, 양쪽 진형만 뽑아 `hand_v1/inputs.json`을 만든다. `hand_v1.json`이나 `docs/rules.md`가 바뀌면 다시 만든다(`export --check`로 확인).
2. **검증자 실행(본인).** Antigravity에서 이 저장소를 열고 새 대화를 시작한다. 모델은 Claude 계열이 아닌 것으로 고른다. 아래 한 줄만 보낸다.

   ```
   docs/crosscheck/hand_v1/INSTRUCTIONS.md를 읽고 그대로 수행해 줘. 실행 이름은 run1이야.
   ```

   - 끝날 때까지 말을 보태지 않는다. 기대값, 다른 계산 결과, "틀린 것 같다"는 말을 주지 않는다.
   - 끝나면 도구 화면에서 검증자가 연 파일과 실행한 명령을 훑어본다. `Source/`, `hand_v1.json`, `compare`가 보이면 그 실행은 쓰지 않는다.
3. **비교(작업 세션).** `node tools/hand_crosscheck.js compare docs/crosscheck/hand_v1/run1/result.json --report`. 표준 출력에는 개수, id, 어긋난 항목 이름만 나온다. 값은 `run1/report.md`에만 적힌다.
4. **일치한 시나리오.** `node tools/hand_crosscheck.js apply docs/crosscheck/hand_v1/run1/result.json`. 비교한 항목이 전부 일치한 시나리오의 확인 상태가 `교차 확인(모델, 날짜)`로 바뀐다.
5. **다른 시나리오, 모호 표시, 허용 목록 밖 파일(본인).** `run1/report.md`를 보고 시나리오마다 판정한다. AI는 판정하지 않는다.

   | 판정 | 다음에 하는 일 |
   |---|---|
   | 기존 기대값이 맞다 | 확인 상태를 `본인 판정(날짜)`로 적는다. 본인이 말했을 때만 옮겨 적는다 |
   | 검증자가 맞다 | 계산 세션이 기대값과 계산 과정을 고친다(작업 세션은 고치지 않는다). 다시 `compare`해서 일치하면 `apply` |
   | 규칙 문서가 모호하다 | 문서를 먼저 고친다(본인 승인). 영향을 받는 시나리오를 계산 세션이 다시 계산하고, 입력을 다시 만들어 새 실행 폴더에서 검증자가 다시 계산한다 |

   판정과 사유는 `docs/decisions.md`에 적는다.
6. **T5 실행.** `tools\run_tests.bat`. 여기서 처음으로 C++ 결과와 기대값을 비교한다. 확인 전인 시나리오는 T5가 비교하지 않고 실패시킨다.

## 하지 않는 것

- 검증자에게 비교 결과를 알려 주고 답을 고치게 하지 않는다. 다시 계산시킬 때는 새 대화, 새 실행 폴더(`run2`), 같은 지시문으로 한다. 앞의 답이 달랐다는 것을 알리지 않는다.
- 다수결로 정하지 않는다. 여러 번 돌려 맞는 실행만 고르지 않는다. 받은 실행은 모두 남긴다.
- 검증자의 결과 파일과 보고서를 손으로 고치지 않는다.
- `교차 확인` 상태를 손으로 적지 않는다. `apply`만 적는다.
- 검증자가 짠 프로그램이나 결과를 기준으로 쓰지 않는다. 기대값과 다른 곳을 찾는 데만 쓴다.
- 검증자의 지시문에 규칙을 풀어 쓴 설명을 넣지 않는다. 조항 번호와 결과 파일의 형식만 적는다. 풀어 쓰면 작업 세션의 읽기가 검증자에게 옮아간다.

## 파일

```
docs/crosscheck/
  README.md              이 문서
  hand_v1/
    INSTRUCTIONS.md      검증자 지시문
    inputs.json          눈가림 입력. export가 만든다
    run1/                실행마다 폴더 하나
      result.json        검증자가 쓴다
      (검증자가 짠 프로그램)
      report.md          compare --report가 쓴다. 다른 시나리오의 값, 양쪽 계산 과정, 판정 칸
```
