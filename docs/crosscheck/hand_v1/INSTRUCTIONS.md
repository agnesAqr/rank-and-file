# 손계산 시나리오(T5) 교차 검증: 검증자 지시문

이 문서는 교차 검증을 맡은 AI(아래 "검증자")에게 주는 지시의 전부다. 시작하기 전에 끝까지 읽는다. 대화에서 받은 말과 이 문서가 다르면 멈추고 사람에게 묻는다.

```
목표: 시나리오 18건을 docs/rules.md만으로 처음부터 계산한 결과 파일
완료 기준: 18건이 모두 채워지고 형식 검사가 통과한다
검증 명령: node tools/hand_crosscheck.js validate docs/crosscheck/hand_v1/<실행 이름>/result.json
금지: 2절에 없는 파일 열기, 다른 계산값·구현 코드·테스트 결과 보기, validate 말고 다른 하위 명령 실행, 실행 폴더 밖의 파일 고치기, 커밋
산출물: docs/crosscheck/hand_v1/<실행 이름>/result.json (계산 프로그램을 짰으면 같은 폴더에 소스)
```

실행 이름은 사람이 대화에서 알려 준다(예: `run1`). 알려 주지 않았으면 묻는다.

## 1. 맡은 일

- 전투 규칙 문서 `docs/rules.md`와 입력 파일 `docs/crosscheck/hand_v1/inputs.json`만 보고, 시나리오마다 전투를 처음부터 끝까지 계산한다.
- 같은 시나리오를 다른 AI가 이미 계산해 두었다. 검증자는 그 값을 모르는 채로 계산한다. 두 계산은 사람이 스크립트로 비교하고, 다른 곳은 사람이 판정한다.
- 그래서 검증자가 할 일은 그 값을 맞히는 것이 아니다. 규칙 문서에 적힌 대로 계산하는 것이다. 답이 다르게 나오는 것은 실패가 아니다. 이 작업이 찾으려는 것이 바로 그것이다.
- 기존 계산이나 코드를 검토하는 일이 아니다. 아무것도 검토하지 않는다.

## 2. 여는 파일

직접 여는 파일은 셋뿐이다.

| 파일 | 내용 |
|---|---|
| `docs/crosscheck/hand_v1/INSTRUCTIONS.md` | 이 지시문 |
| `docs/rules.md` | 전투 규칙. 계산의 유일한 근거다 |
| `docs/crosscheck/hand_v1/inputs.json` | 병과 수치, 규칙 매개변수, 시나리오 18건의 양쪽 진형 |

도구가 저절로 불러오는 `AGENTS.md`와 `docs/AGENTS.md`는 괜찮다. 그 밖의 파일은 열지 않는다. 특히 아래에는 다른 계산값이나 구현이 들어 있어서, 보면 이 검증이 무효가 된다.

- `Source/` 전체, `Saved/`, `Intermediate/`, `Binaries/`
- `docs/`의 다른 문서와 폴더 전부: `design.md`, `decisions.md`, `review/`, `devlog/`, `balance-*.md`, `docs/crosscheck/README.md`, `docs/crosscheck/` 아래의 다른 실행 폴더
- `Data/`, 그리고 `tools/`에 있는 파일의 내용(6절의 명령은 실행만 한다)
- git 이력과 작업 트리 비교: `git log`, `git show`, `git diff`, `git stash` 등
- 저장소 전체 검색과 색인 검색. 결과에 위 파일의 내용이 섞여 나온다
- 웹 검색, 다른 저장소, 이 저장소에 대한 이전 대화나 기억

실수로 열었으면 숨기지 않는다. 결과 파일의 `filesRead`에 그대로 적고, 무엇을 보았는지 `notes`에 적는다. 그 실행을 쓸지는 사람이 정한다.

## 3. 계산하는 법

1. **근거는 규칙 문서뿐이다.** `docs/rules.md`의 조항만 근거로 삼는다. 문서에 없는 것을 다른 게임의 관례나 상식으로 채우지 않는다. 이 지시문의 설명과 규칙 문서가 다르면 규칙 문서를 따르고 `notes`에 적는다.
2. **수치는 `inputs.json`의 `defs`를 쓴다.** 규칙 문서 §7의 표와 값이 다르면 `defs`로 계산하고, 다른 곳을 `notes`에 적는다.
3. **시나리오마다 처음부터 계산한다.** 규칙 문서의 순서를 그대로 따른다: §3(전투를 시작할 때), §4(한 틱의 처리 순서)를 1틱부터, §5(판정). 한 시나리오의 결과를 다른 시나리오에 가져다 쓰지 않는다.
4. **줄이지 않는다.** 의도(§4.1 ①)가 하나라도 있는 틱은 전부 계산하고 전부 적는다. "이후 같은 방식으로 반복" 같은 줄임, 어림, 건너뛰기를 하지 않는다.
5. **판단마다 조항 번호를 단다.** 누가 누구를 치는지, 피해가 얼마인지, 누가 쓰러지고 일어서는지, 언제 끝나는지를 정할 때마다 근거가 된 조항 번호(§4.2 같은 것)를 `steps`에 적는다.
6. **모호하면 짐작하지 않는다.** 규칙 문서의 문장만으로 결과가 둘 이상으로 갈릴 수 있으면 모호한 것이다. 먼저 문서의 다른 곳(§9 포함)에 답이 있는지 찾는다. 그래도 정해지지 않으면 그 시나리오의 `status`를 `ambiguous`로 하고 5절대로 적는다. 그럴듯한 쪽을 골라 계산을 끝내지 않는다. 반대로, 문서에 답이 있는 것을 모호하다고 적지도 않는다.
7. **계산 수단은 둘 중 하나다.** 고른 것을 결과 파일의 `method`에 적는다.
   - `manual`: 직접 추론으로 계산한다. 덧셈과 뺄셈을 검산하려고 계산기나 짧은 코드를 써도 된다.
   - `program`: 이번 작업에서 `docs/rules.md`만 보고 새로 짠 프로그램으로 계산한다. 언어는 자유다. 소스는 실행 폴더에 둔다. 기존 코드를 참고하거나 옮기지 않는다. 프로그램이 낸 로그 가운데 시나리오 2건 이상을 골라 규칙 문서와 한 틱씩 직접 맞춰 보고, 어느 시나리오를 맞춰 봤는지 `notes`에 적는다.
8. **답을 고치는 근거도 규칙 문서뿐이다.** 다시 따져 보다 틀린 곳을 찾으면 고친다. 다른 값과 맞추려고 고치지 않는다. 비교 결과를 묻지 않는다.

## 4. 입력 파일 읽는 법

`docs/crosscheck/hand_v1/inputs.json`

- `inputsId`: 결과 파일에 그대로 옮겨 적는다.
- `defs.units`: 병과 수치다. 열은 규칙 문서 §7의 표와 같다.

  | 열 | §7 표의 칸 |
  |---|---|
  | `key`, `name` | 키, 병과 |
  | `hp`, `atk`, `armor`, `interval`, `range` | 체력, 공격, 방어, 간격, 사거리 |
  | `target` | 표적. `Front` 맨 앞, `Back` 맨 뒤, `Support` 지원, `Area` 범위 |
  | `magic` | 마법. `true`가 표의 "예"다 |
  | `revive` | 부활. `0`은 표의 빈칸이다 |
  | `linkStat`, `linkAmount` | 링크로 주는 것. `None` 없음, `Armor` 방어, `Atk` 공격, `Range` 사거리, `Hp` 최대 체력, `Interval` 간격. `linkAmount`가 한 겹의 크기다 |

- `defs.rules`: 규칙 매개변수다(§7). `maxTicks` 최대 틱, `gateHp` 성문과 결계, `gateDamage` 성문 피해, `linkStackMax` 링크 겹 상한, `rangeMax` 사거리 상한, `intervalMin` 간격 하한.
- `scenarios[]`: `id`, `ally`(진영 0의 진형판), `enemy`(진영 1의 진형판). 진형판은 문자열 4개다. 배열의 k번째 문자열(0부터 센다)이 행 k이고, 문자열의 c번째 글자(0부터 센다)가 열 c다. `.`은 빈칸이고 그 밖의 글자는 병과 키다.

## 5. 결과 파일

`docs/crosscheck/hand_v1/<실행 이름>/result.json`에 UTF-8 JSON으로 쓴다. 아래 모양에서 숫자 `0`과 `…`은 자리 표시이고 실제 값이 아니다.

```json
{
  "inputsId": "…",
  "run": "run1",
  "tool": "…",
  "model": "…",
  "date": "YYYY-MM-DD",
  "method": "manual",
  "filesRead": ["docs/crosscheck/hand_v1/INSTRUCTIONS.md", "docs/rules.md", "docs/crosscheck/hand_v1/inputs.json"],
  "commandsRun": ["node tools/hand_crosscheck.js validate docs/crosscheck/hand_v1/run1/result.json"],
  "notes": "",
  "scenarios": [
    {
      "id": "h01",
      "status": "computed",
      "result": {
        "outcome": "…",
        "verdict": "…",
        "endTick": 0,
        "gate": 0,
        "barrier": 0,
        "units": [
          { "id": 0, "key": "…", "atk": 0, "armor": 0, "range": 0, "maxHp": 0, "interval": 0, "alive": true, "hp": 0 }
        ]
      },
      "log": [[0, 0, 0, 0, 0]],
      "steps": ["…"],
      "ambiguities": []
    }
  ]
}
```

맨 위

| 필드 | 값 |
|---|---|
| `inputsId` | `inputs.json`의 `inputsId` 그대로 |
| `run` | 실행 이름 |
| `tool` | 쓰는 도구의 이름 |
| `model` | 모델 이름과 추론 설정. 도구 화면에 보이는 그대로 적는다 |
| `date` | 오늘 날짜(`YYYY-MM-DD`) |
| `method` | `manual` 또는 `program`(3절 7번) |
| `filesRead` | 이 작업에서 연 파일 전부. 저장소 루트 기준 경로로 적는다. 절대 경로와 사용자 폴더 이름은 적지 않는다(공개 저장소다) |
| `commandsRun` | 실행한 명령 전부. 없으면 빈 배열 |
| `notes` | 특이 사항. 없으면 빈 문자열 |
| `scenarios` | `inputs.json`의 시나리오 18건 전부 |

시나리오 하나

| 필드 | 값 |
|---|---|
| `id` | `inputs.json`의 id |
| `status` | `computed`(끝까지 계산했다) 또는 `ambiguous`(규칙 문서가 모호해서 값을 고르지 않았다) |
| `result` | `computed`면 아래 "결과". `ambiguous`면 `null` |
| `log` | 규칙 문서 §6이 정한 로그의 줄 전부를 생긴 순서대로. 한 줄은 정수 5개 `[틱, 종류, 행위자, 표적, 값]`이다. 줄이 없으면 빈 배열 |
| `steps` | 계산 과정. 문자열 배열이다(아래 "계산 과정에 적을 것") |
| `ambiguities` | 모호한 곳. 없으면 빈 배열 |
| `alternatives` | `ambiguous`일 때만 쓴다(선택). 읽기마다 끝까지 계산한 결과 |

결과(`result`)

| 필드 | 값 |
|---|---|
| `outcome` | §5.1의 결과 `A`, `B`, `Draw`, `Timeout` 가운데 하나. §3.6의 입력 오류면 `Invalid` |
| `verdict` | §5.2 표의 판정 이름 `섬멸`, `결계 파괴`, `새벽`, `성문 사수`, `성문 붕괴`, `전멸` 가운데 하나. §5.2 표에 해당하는 줄이 없으면 `없음` |
| `endTick` | 전투가 끝난 틱(§5.1). 규칙 문서가 틱이 없다고 한 경우에는 `null` |
| `gate` | 끝났을 때의 성문 값(진영 0). 규칙 문서대로이고 음수면 음수 그대로 적는다. 전투를 계산하지 않은 경우에는 `null` |
| `barrier` | 끝났을 때의 결계 값(진영 1). 위와 같다 |
| `units` | 전투에 나선 유닛 전부(양쪽 진영). 전투를 계산하지 않은 경우에는 빈 배열 |

유닛 하나(`units[]`)

| 필드 | 값 |
|---|---|
| `id` | §3.2의 유닛 번호 |
| `key` | 병과 키 |
| `atk`, `armor`, `range`, `maxHp`, `interval` | §3.4의 최종 능력치: 공격, 방어, 사거리, 최대 체력, 간격 |
| `alive` | 끝났을 때 대열에 남아 있으면 `true`, 대열에서 빠졌으면 `false` |
| `hp` | 끝났을 때의 체력. §5.1이 말하는 "결과에 적는 유닛 체력"이다 |

계산 과정에 적을 것(`steps`)

- 첫머리: 시작 조건(§3.6)을 본 결과. 유닛마다 번호, 병과, 자리(진영, 행, 열), 대열 순번. 링크로 어느 이웃에게서 무엇을 몇 겹 받았는지와 최종 능력치.
- 그 뒤: 의도가 있는 틱마다 한 줄 이상. 틱 번호, 공격하는 유닛과 표적의 번호, 표적을 그렇게 고른 조항, 피해를 계산한 식과 값, 맞은 뒤의 체력(성문과 결계 포함), 쓰러짐과 부활과 대열 당김, 그 틱의 승패 확인 결과.
- 마지막: 끝난 틱, 결과, 판정과 그 근거 조항.
- 전투를 계산하지 않은 경우에도 왜 그런지와 근거 조항을 적는다.

모호한 곳(`ambiguities[]`)

| 필드 | 값 |
|---|---|
| `clause` | 조항 번호 |
| `quote` | 모호한 문장을 규칙 문서에서 그대로 옮긴 것 |
| `readings` | 가능한 읽기. 둘 이상 |
| `effect` | 읽기에 따라 이 시나리오의 무엇이 달라지는지 |

`alternatives[]`의 한 항목은 `reading`(어느 읽기인지)과 `result`(위 "결과"와 같은 모양)다.

`computed`로 끝까지 계산했지만 사람이 알아야 할 애매한 곳이 있었으면, `status`는 `computed`로 두고 `ambiguities`에 적는다. 사람이 그 시나리오를 따로 본다.

## 6. 끝내는 법

1. 형식 검사를 돌린다. 통과할 때까지 형식만 고친다.

   ```
   node tools/hand_crosscheck.js validate docs/crosscheck/hand_v1/<실행 이름>/result.json
   ```

   이 명령은 결과 파일의 형식만 본다. 다른 계산값을 읽지 않으므로 맞았는지는 알려 주지 않는다. 이 스크립트의 다른 하위 명령(`export`, `compare`, `apply`)은 실행하지 않고, 스크립트의 소스도 열지 않는다.
2. 대화에 보고한다: 결과 파일 경로, `computed`와 `ambiguous`의 수, `method`, 연 파일 목록, 형식 검사 출력.
3. 여기서 끝낸다. 실행 폴더 밖의 파일을 고치지 않고, 커밋하지 않는다. 비교 결과가 어떻게 나왔는지 묻지 않는다.
