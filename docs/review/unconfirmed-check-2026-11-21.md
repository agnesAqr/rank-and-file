## 끝내 확인하지 못한 것과 확인 방법

1. T11의 실제 Shipping 패키지 시험(7, 8번). 소스와 실행 기록으로는 막는 곳이 없지만 T11 코드를 넣은 패키지로 돌려 본 적은 없다. 남은 것은 t11 조사 문서 8절의 1~5번이다: 인자 전달과 결과 파일, `StartupModule` 시점에서 강제 종료했을 때 결과 파일과 종료 코드, `-nullrhi`로 모듈 시작까지 가는지, 스크립트가 창 프로그램의 종료 코드를 받는지, 부트스트랩 `RankAndFile.exe`가 인자와 종료 코드를 넘기는지. 확인 방법: 기준 확정 뒤 T11 코드를 넣은 첫 패키지에서 정상 인자 1번, 틀린 인자(상대 경로) 1번, `-nullrhi`를 붙인 것과 뺀 것을 한 번씩 돌려 결과 파일과 스크립트가 받은 종료 코드를 본다.
2. 데이터 에셋 쿠킹의 실제 동작(11번). 지금 프로젝트가 "요청 0개" 상태라 전체 쿠킹 단계가 도는지는 기록으로 알 수 없었다. 11/20과 11/21 23:19 쿠킹 기록에는 전체 쿠킹이 찾은 것이 없을 때 나오는 "No packages found for parameter"와, 요청이 없을 때의 경고 "No package requests specified"가 둘 다 없다(`CookOnTheFlyServer.cpp:8973, 8985`). 그런데 쿠킹할 프로젝트 에셋도 없었다. 확인 방법(사람 승인 뒤, 설정을 바꾸는 단계는 따로 승인): ① 아무도 참조하지 않는 데이터 에셋 하나를 둔 채 `tools\package.bat`을 돌려 `Saved/StagedBuilds/Windows/Manifest_UFSFiles_Win64.txt`에서 찾는다 ② 맵을 `MapsToCook`에 넣고 다시 돌려 빠지는지 본다 ③ 고른 방법(`PrimaryAssetTypesToScan` 등)을 넣고 다시 들어가는지 본다.
3. `AddRow`로 만든 DataTable 에셋의 저장·다시 열기·쿠킹(4~6번). API와 동작은 소스로 확인했지만 이 프로젝트의 행 구조체로 저장해 본 적은 없다. 확인 방법: 임포터를 만든 뒤 T8(행 수 일치), 대소문자만 다른 `id` 두 개를 넣은 입력으로 임포터가 실패하는지, 저장한 에셋을 에디터에서 다시 열어 행 수를 본다.
4. MCP를 켠 뒤 Shipping 패키지에 MCP가 없는지(13번). 지금 다른 작업(11/21 병렬 작업 ④)이 확인하고 있다. 확인 방법: 그 작업의 패키지에서 `netstat -ano | findstr :8000`(LISTENING 0줄)과 스테이징 폴더 검색(`ModelContextProtocol`, `ToolsetRegistry`, `EditorToolset`, `UMGToolSet`, `PythonScript` 0줄).
5. `BindWidget`의 실제 컴파일 메시지(1, 2번). 동작은 소스로 확인했다. 실제 메시지는 2단계에서 MCP로 위젯 블루프린트를 만들 때 컴파일 결과(필수 바인딩 누락 0건)로 본다.
6. 애니메이션 끊김(14번)은 확인할 대상이 아니라 사람의 판정이다. 고칠 문장 안에서 [미정]으로 바꿨다.
