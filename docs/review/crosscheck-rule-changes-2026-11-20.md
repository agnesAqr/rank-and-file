## 1. 정해진 것과 정할 것

본인이 말한 것(11/20, `docs/decisions.md`)

- 사람 확인 대신 다른 AI 모델로 교차 검증한다.
- 교차 검증은 Antigravity에서 이 저장소 경로로 한다. 결과가 서로 다른 경우만 본인이 본다.
- 검증 방법과 지시를 명확히 정한다.

AI 제안(승인이 필요하다)

| # | 정할 것 | 제안 | 다른 선택지 |
|---|---|---|---|
| 1 | 범위 | T5, 특성 예제(T7), 수치·규칙을 바꾼 뒤의 재계산, 새 테스트의 손계산 기대값 모두 | T5만 |

2번의 근거 [판단]: 프로그램은 덧셈 실수가 없고 틱 로그를 빠짐없이 낸다. 기존 기대값은 손 계산이라, 방법이 달라야 같은 종류의 실수를 함께 하지 않는다. 대신 프로그램 한 곳이 틀리면 여러 시나리오가 한꺼번에 다르게 나온다(원인은 하나다). 프로그램도 AI가 짰고 사람이 검증하지 않았으므로 기준으로 쓰지 않고, 기대값과 다른 곳을 찾는 데만 쓴다(11/17 "JS 참조 구현을 기준으로 쓰지 않는다"와 같은 원칙).

## 2. 절차 요약

전체는 `docs/crosscheck/README.md`, 검증자에게 주는 지시는 `docs/crosscheck/hand_v1/INSTRUCTIONS.md`다.

| 결함이 지나가는 길 | 막는 장치 |
|---|---|
| 검증자가 기존 답이나 구현을 보고 따라간다 | 눈가림 입력(수치와 진형만. 기대값, 계산 과정, 목적, 조항 번호 없음). 여는 파일을 셋으로 제한. 연 파일과 실행한 명령을 결과에 적게 하고, 허용 목록 밖이면 스크립트가 알린다. 본인이 도구 화면에서 확인한다 |
| 검증자가 기존 계산을 "검토"하며 동의한다 | 검토시키지 않는다. 처음부터 계산시킨다 |
| 모호한 문장을 그럴듯하게 정하고 넘어간다 | 짐작 금지. `ambiguous`로 표시하게 하고, 모호 표시는 불일치와 똑같이 본인이 본다 |
| 긴 계산을 줄이거나 어림한다 | 의도가 있는 틱을 전부 적게 한다. 판단마다 조항 번호. §6 형식의 로그 전체를 내게 한다 |
| 비교 결과를 듣고 답을 맞춘다 | 검증자는 형식 검사(`validate`)만 돌린다. 비교 결과를 알려 주지 않는다. 다시 계산은 새 대화, 새 실행 폴더에서 한다 |
| 지시문이 작업 세션의 읽기를 옮긴다 | 지시문에는 조항 번호와 결과 형식만 적는다. 규칙을 풀어 쓰지 않는다. 스크립트에도 규칙을 해석하는 코드를 넣지 않는다 |
| 두 계산이 다른데 AI가 한쪽을 고른다 | 다수결 없음. 다른 곳은 본인이 판정한다. 작업 세션은 개수, id, 항목 이름만 본다 |
| 확인 상태를 근거 없이 올린다 | `교차 확인`은 `apply`만 적는다. 전 항목이 일치한 시나리오만, 확인 상태 글자만 바꾼다 |
| 검증 뒤에 시나리오, 수치, 규칙 문서가 바뀐다 | 결과 파일에 `inputsId`를 옮겨 적게 하고, 비교할 때 지금 파일로 다시 계산한 값과 다르면 비교하지 않는다 |

교차 검증으로 못 잡는 것: 두 모델이 같은 문장을 같은 식으로 잘못 읽은 경우 [판단], 시나리오가 목적으로 적은 상황을 실제로 지나는지(값만 비교한다). 변이 검사와 대조표 리뷰가 맡는다.
