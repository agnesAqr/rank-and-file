# docs/ 작업 규칙

문서는 코드의 명세이고 판단의 기록이다. 루트 `AGENTS.md`를 먼저 읽는다.

## 파일

| 파일 | 내용 | AI가 하는 일 |
|---|---|---|
| `rules.md` | 전투 규칙 여덟 조항, 유닛 생성과 링크, 한 틱의 처리 순서, 이벤트와 해시 | 초안 쓰기, 모호한 곳 찾기. 조항 확정은 사람 |
| `design.md` | 설계도: 모듈, 데이터 형식, 테스트, 개발 순서, 미정 사항 | 변경안 제안. 구조를 바꾸는 결정은 사람 |
| `background.md` | 배경 기획: 색 조건, 생성할 이미지 3장의 사양·프롬프트·선별 기준 | 사양을 바꾸자는 제안만. 콘셉트와 채택은 사람 |
| `balance-2026-11-15.md` | 기획 단계 밸런스 점검(JS로 낸 [산정] 값) | 기록이다. 고치지 않는다. 새 점검은 새 파일로 |
| `decisions.md` | 결정 기록 | 사람이 말한 결정을 옮겨 적고, 자기 안은 "검토 중 · AI 제안"으로 적는다 |
| `devlog/YYYY-MM-DD.md` | 개발 일지. 하루에 파일 하나 | 사실 칸만 채운다(아래) |
| `crosscheck/` | 교차 검증: 절차(`README.md`), 검증자 지시문, 눈가림 입력, 실행마다의 검증자 결과와 비교 보고서 | 절차와 지시문의 수정안 제안. 눈가림 입력과 보고서는 `tools/hand_crosscheck.js`로만 만든다. 검증자 결과는 고치지 않는다 |

## rules.md

- `RankCore`의 명세다. 구현하는 쪽이 임의로 정하게 되는 곳(동점, 처리 순서, 경계값)은 모두 조항으로 적혀 있어야 한다. 빠진 곳을 찾으면 코드로 메우지 않고 목록으로 알린다.
- 조항을 바꾸면 같은 변경 안에서 `RankCore`와 손계산 시나리오를 함께 맞추고, 사람의 승인을 받아 회귀 테스트 결과를 다시 기록한다(`tools\record_regression.bat`). 하나라도 빠지면 끝난 것이 아니다.
- 조항 번호는 한번 붙이면 바꾸지 않는다. 코드 주석과 테스트가 번호로 조항을 가리킨다(예: `§2.2`, `§2.5`).
- 손계산 시나리오의 기대값은 AI가 `docs/rules.md`만 보고 계산하고, 다른 회사 모델이 따로 계산해 비교한다. 다른 곳만 사람이 판정한다(`docs/crosscheck/README.md`). AI는 틱마다의 계산 과정을 함께 적는다. 구현 결과를 보고 기대값을 고치지 않는다(자세한 규칙은 `Source/RankTests/AGENTS.md`).

## decisions.md

| 날짜 | 결정 | 검토한 대안 | 근거 | 상태 |
|---|---|---|---|---|

- 상태는 `확정 · 본인`, `검토 중 · AI 제안`, `변경(날짜)`, `폐기` 가운데 하나다.
- 지난 결정을 지우거나 덮어쓰지 않는다. 바뀌면 새 행을 더하고 예전 행의 상태에 바뀐 날짜를 적는다.
- 수치를 바꾼 결정에는 바꾸기 전과 후의 값, 근거가 된 시뮬레이션의 조건(명령, 시드, 판 수, 콘텐츠 버전 해시)을 적는다.
- AI가 낸 안을 사람이 버리거나 고쳤으면 그 이유도 남긴다.
- `RankCore` 기준 확정은 "확정 · 본인" 행으로 남긴다: 커밋, 통과한 테스트와 수, 리뷰한 범위. 회귀 테스트 결과를 다시 기록하면 바뀐 대전과 이유를 적는다.

## devlog

하루에 파일 하나, 네 칸이다.

```
# 2026-11-16

## 맡긴 것
## 내가 판단한 것
## 검증한 방법
## 버리거나 고친 것
```

- "내가 판단한 것"은 사람의 칸이다. AI는 그날 사람이 실제로 말한 결정만 옮겨 적고, 없으면 비워 둔다. 판단을 지어내지 않는다.
- "맡긴 것"과 "검증한 방법"은 실제로 실행한 명령과 그 결과로 적는다.
- "버리거나 고친 것"에는 AI 산출물 가운데 버리거나 고친 것과 이유를 적는다. AI가 틀린 것을 빼지 않는다.
- AI로 이미지를 만든 날에는 도구 이름, 프롬프트, 후보 수, 고른 것과 버린 것의 이유를 적는다.

## 표기

- 수치 라벨은 [초기값], [산정], [측정]이다. 측정값에는 조건을 붙인다(루트 7절).
- [제안] 확정되지 않은 안, [미정] 사람의 결정이 필요한 것, [미확인] 확인하지 못한 것(확인 방법을 함께 적는다), [판단] 근거를 붙인 의견.
- 엔진 동작이나 라이선스 같은 외부 사실에는 출처 링크를 단다.
- 한국어로 쓴다. 기술 용어는 처음 나올 때 영문 원어를 함께 적는다. 줄표(—)는 쓰지 않고 쌍점, 괄호, 가운뎃점을 쓴다.
