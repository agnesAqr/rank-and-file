## 버리거나 고친 것

- 줄 끝 형식: AI가 "모든 파일이 CRLF"라고 잘못 보고했다. 확인에 쓴 `grep`이 CR을 세지 못했다. 실제로는 `RankContent.cpp`·`RankContent.h`, `hand_v1.json`, 교차 검증 문서 3개 등 6개 파일이 LF만 쓴다(한 파일 안에서 섞이지는 않았다). 저장소에는 LF로 들어가 내용에는 영향이 없다(작업 세션 기록)
  - 일지를 쓰며 다시 셌다 [측정, 2026-11-21, 커밋 `099f906`의 작업 트리]: 오늘 커밋 7개(`d3d0b11`~`099f906`)에서 바뀐 파일 29개를 `git ls-files --eol`로 보면 저장소(index)는 29개 모두 LF, 작업 트리는 CRLF 9개, LF 20개, 한 파일 안에서 섞인 것 0개다. LF만 쓰는 파일 수가 작업 세션 기록의 "6개"와 다른 것은 센 범위가 달라서다. 그때의 6개는 커밋 전 `git diff --stat`에서 git이 줄 끝 경고를 낸 파일(이미 추적하던 파일 가운데 LF인 것)이었다. 새로 만든 파일과 그 뒤에 고친 문서(개발 일지, 검토 문서, `README.md`)는 들어 있지 않았다(작업 세션 기록)
